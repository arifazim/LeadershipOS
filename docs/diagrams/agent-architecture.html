Engineering Manager OS — System Schematic

How the agents connect

Eight subagents, eleven reusable loops, and the shared layers underneath them. Orchestrator routes to specialists; specialists run loops; loops invoke skills, honor contracts, and log to memory; kaizen watches all of it and rewrites the rest.

01 Request → Orchestrator → Specialists

A request lands with the engineering-manager subagent, which routes it — sometimes to one specialist, sometimes to several in parallel — then synthesizes their outputs. Two specialists (tech-lead, product-partner) hand off deeper work to others rather than reporting straight back.

02 Anatomy of one loop

Every one of the eleven loops — sprint-loop, incident-loop, career-loop, and eight others — runs the same five steps. A loop is what makes a subagent's routing reusable and cadence-bound instead of ad hoc.

01
Gather Inputs
Pull data via the relevant integration — GitHub, Jira, PagerDuty, Datadog.
integrations/*.md
02
Invoke Skills
Run the domain skill(s) that do the actual analysis, in sequence or with branches.
skills/<domain>/*.md
03
Route to Subagent(s)
Hand the analysis to whichever subagent owns the judgment call.
subagents/*.md
04
Produce Output
Render the result into a standard, fillable artifact.
templates/*.md
05
Log Outcome
Write what happened to the matching memory domain — never a generic file.
memory/<domain>/

03 Same territory, different loop

Two pairs of loops sit close enough to collide. Each one names the boundary explicitly in its own Related Loops section, so the split doesn't erode back into one loop guessing at the other's job.

sprint-loop vs delivery-loop
SPRINT-LOOP

The single-sprint ceremony — plan, execute, review one cycle.

DELIVERY-LOOP

The rolling, cross-sprint DORA trend — is delivery health improving or decaying.

career-loop vs promotion-loop
CAREER-LOOP

The ongoing, multi-year development conversation — direction, sponsorship, growth.

PROMOTION-LOOP

The bounded execution of one specific promotion cycle, once career-loop has set direction.

04 Kaizen — the loop that watches the loops

Loop Engineering improves within a task. Kaizen improves the system itself. Every completed activity becomes training data for the next decision — this is the cycle that rewrites playbooks, prompts, skills, and memory when a recommendation turns out wrong.

Every quarterthis cycle repeats — the OS should be measurably smarter each time
